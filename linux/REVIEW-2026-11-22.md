# OrderlySTT Linux 侧全面 Review（2026-11-22）

**范围**：`linux/orderlystt.py`（生产守护）、`linux/install.sh` / `uninstall.sh`、systemd 用户单元、
`/data/orderlystt/config.json`、SenseVoice 模型、polish 层、仓库 git 状态、历史故障记录。
**方法**：逐行读源码；实测运行时/依赖/模型/注入链路；核对 journal 与日记证据；隔离 venv 做 E2E 识别验证。
**结论先行**：11/5 的「炎症」是**运行时版本耦合 + systemd 无启动限流**造成的重启风暴，不是识别逻辑出错。
两处都必须改，否则再次 `enable --now` 必然复现。

### P1 — 卡死 / 静默失败 / 不可回溯

| # | 位置 | 问题 |
|---|---|---|
| P1-1 | `record_ptt` / `record_silence` | arecord 退出后管道 EOF，`os.read` 返回空却不 break；`select` 对已关闭管道持续可读 → 最长 30s 满核空转。`record_silence` 里 `if not chunk: pass` 明确忽略 EOF。与 9/29 空转同机理 |
| P1-2 | `Keyboards.scan()` | 只增不减：节点重枚举后旧 fd 不主动 drop，仅靠读到 EOF 才清；应做路径差集清理并给 `drain()` 加迭代上限 |
| P1-3 | `daemon()` | 键盘无权限 / `Engine(cfg)` 抛异常 → `sys.exit(1)` → 被 systemd 当失败无限重启；应有界重试后以 75 退出 |
| P1-4 | `deliver()` | 忽略 `set_clipboard()` 返回值、不检查 `ydotool` 退出码；剪贴板或注入失败时仍盲发 Ctrl+V，静默丢字 |
| P1-5 | `daemon()` | 启动无条件 `os.remove(SOCK)` 会摘掉正在运行的实例；unix socket 权限随 umask（非 600），任何本地用户可发 `record` 触发录音 |
| P1-6 | `install.sh` | config 写 `../models/...` 相对路径；提示「日志: $PREFIX/daemon.log」但日志实际在 journal（误导）；`enable --now` 后只 sleep 1 就报成功，无健康校验 |
| P1-7 | `uninstall.sh` | 仍 `pkill -f "vernest[.]py daemon"`，杀不到 orderlystt；不 stop/disable unit |
| P1-8 | 仓库 | 生产脚本 `linux/orderlystt.py` 处于 untracked，install 脚本改动未提交；无 requirements、无版本锁定 → 不可回溯 |

## 加固设计（已确认口径）

1. **运行时解耦**：`uv venv --python 3.14` 建独立 venv（`/data/orderlystt/venv`），
   `linux/requirements.txt` 锁定 `sherpa-onnx==2.0.2 / numpy==2.5.5 / soundfile==0.14.0`；
   删除 `sys.path` 硬编码。系统 Python 再升级也不影响（uv 会找/下载 3.14）。
   **可行性已实测**：cp314 manylinux wheel 4.4MB，隔离 venv 中用 2024-07-17 的 SenseVoice int8 模型
   对 zh/en/ja/ko/yue 五个样本 wav 全部正确转写（`zh.wav -> 开饭时间早上9点至下午5点。`）。
2. **崩溃防循环**：unit 加 `StartLimitIntervalSec=300 StartLimitBurst=3 RestartSec=10
   RestartPreventExitStatus=75 TimeoutStartSec=60 LogRateLimitIntervalSec=30 LogRateLimitBurst=20`；
   daemon 对永久错误（依赖/模型/键盘权限）有界重试后 `exit 75`。
3. **防卡死**：arecord EOF / 进程退出即 break；`scan()` 路径差集清理；`drain()` 迭代上限；
   静音模式无人说话 8s 提前收工。刻意不打心跳日志（避免 journal 噪音），所有阻塞调用已有 2.5~8s 超时。
4. **注入链路**：剪贴板失败不盲发；`ydotool` 用 `check=True` 并通知失败；socket `chmod 600` + 单实例检测。
5. **安装脚本**：删除 GNOME 快捷键注册（改为清理残留）；绝对路径；建 venv + 装依赖；
   `systemctl is-active` + `status` 健康校验，失败打印 journal 尾巴并非零退出；uninstall 修正进程名与 unit 停止。
6. **默认关闭润色**：新增 `polish_enabled=false`，零网络调用；开启时 DeepSeek 走环境代理（不再 no-proxy）。
   key 仍走 install.sh 终端录入 + chmod 600，不进聊天。
7. **可回溯**：review 报告 + 全部改动 commit 到 `polish` 分支并推送 `orderly/polish`。
